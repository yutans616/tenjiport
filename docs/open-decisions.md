# 残る判断事項

作成日：2026-09-08

設計・実装は以下が未決のままでも進められる。仮値を確定条件として扱わず、本番課金・本番公開の前に確定する（ブリーフ14章 + 本計画でのブラッシュアップ追加分）。

| 項目 | 現状 |
|---|---|
| サービス名・ドメイン | 確定。TenjiPort／tenjiport.com |
| 通常プランの最終価格・税処理 | 確定。1開催9,800円（税込）／30社まで、31社目から1社300円（税込）。`pricing_configs`に`is_test=false`で投入済み |
| 通常プランの締め日・最終精算 | 確定。月次精算ではなく、基本料金はイベント作成時に即時課金、超過分はイベント終了日起点で自動課金（1イベント＝1回の利用単位） |
| 年間プラン | 確定。年額298,000円／年間6開催・各開催300社まで（未使用枠は開催間で合算不可）。年間7開催以上・1開催301社以上は個別見積もり（年額298,000円を基本の出発点に算定）。`annual_plan_configs`に`is_test=false`で投入済み |
| 上限超過時・決済失敗時の操作制限 | 確定。通知のみ・利用制限なし（既存イベント・新規イベント作成とも継続可能）。ただし通常プランの新規イベント作成自体は、プラン未選択の組織に限り`/plan`へ誘導する |
| 参加取消・重複登録の課金訂正 | 本番課金前に確定。構造としては`usage_ledger`の`correction_credit`/`correction_debit`で対応可能 |
| 開催利用期間・保存期間・ファイル容量 | 未定。設定値化する |
| 複数担当者・権限・グループの詳細 | 最小構成（owner/admin/staff、owner/staff）を実装、詳細は運用しながら調整 |
| 実際の入力項目と出力様式 | 既存PDF・Excelが入手でき次第具体化 |
| インボイス制度（適格請求書）対応 | `ServiceInvoice`（利用料請求）への適格請求書発行事業者登録番号の記載要否が未検討。消費税の扱いと合わせて確定が必要（ブラッシュアップ提案3） |
| 特定商取引法に基づく表記の記載内容 | 確定。`/legal/tokushoho`に正式な事業者情報を記載済み（メールアドレスのみ暫定の可能性あり、要最終確認） |
| Stripe自動課金・Webhook | 実装・本番動作確認済み。カード登録、Webhook（本番ダッシュボード登録済み・署名検証・冪等性）、基本料金のイベント作成時即時課金、超過分のイベント終了日起点自動課金、自動再試行まで一通り稼働。**ただしStripeのAPIキー・Webhookとも現在はテストモードのまま**。実際に課金を開始するにはライブモードのAPIキー取得＋別途ライブ用Webhook登録＋Vercel環境変数更新が必要（テスト/ライブは完全に別物）。また、3Dセキュア等の追加認証が必要なカードは現状「課金失敗」扱いになる仕様のため、本番移行時に要考慮 |
| 決済プロバイダの最終選定 | Stripeで実装済み・稼働中。Komoju/PAY.JP等との比較検討は行っていないが、Stripeでの運用を前提として進めている |
| Phase 2の未実装項目 | ①CAPTCHA（Cloudflare Turnstile）は実装済み（2026-09-11）。メールアドレス入力（OTP請求）画面にのみ設置、イベントごとに主催者が任意でON/OFF可能（デフォルトOFF）。`NEXT_PUBLIC_TURNSTILE_SITE_KEY`/`TURNSTILE_SECRET_KEY`が未設定の間は、主催者向けのON/OFFトグルUI自体が表示されず機能は完全に不活性（キー取得・設定はユーザー側の作業として未対応のまま） ②ファイル添付・繰り返し入力タイプのフィールドは実装済み（繰り返し入力は2026-09-11実装。サブ項目はカンマ区切りのラベル指定のみ、型は常に1行テキスト） ③1ユーザー1ブランド限定は実装済み（2026-09-11）。新規イベント応募時、既存ブランドが2件以上ある場合のみ「既存ブランドで続ける／新しいブランドとして応募する」の選択を挟む（ブランドが1件のみ・0件の場合や、そのイベントへの参加履歴が既にある場合は今まで通り無摩擦）。ブランド管理・切り替え用の専用画面や、出展者間のチーム招待（同一ブランドへの同僚追加）は未実装のまま |
| Supabaseプロジェクト | アカウントは別プロジェクト（広告健康診断SaaS）で作成済み。本SaaS用には新規プロジェクト作成を推奨（テナント・請求・障害影響範囲の分離のため）。作成後、URL/anon key/service role keyを`.env.local`へ設定（チャット等には貼らないこと） |
| 主催者側のメール確認 | 開発中はSupabase Authの Providers > Email > Confirm email をOFFにして動作確認している（カスタムSMTP未設定のため）。本番公開前にONへ戻し、確認メールリンクのテンプレート設定（`/auth/confirm`形式）とSMTP（Resend等）を設定すること |

未決事項があっても画面・データ・テスト環境の設計は進められる。
